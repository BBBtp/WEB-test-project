# Wells API - REST API для системы оценки риска ТГВ/ТЭЛА

## ⚠️ Важные замечания

1. **RSA токены** зашифрованы и содержат `username:session_id`
2. **Сессии хранятся в Redis** - при перезапуске Redis сессии могут быть потеряны
3. **Lua эндпоинты требуют прав модератора** - убедитесь, что пользователь имеет `is_staff=True`
4. **Токен действителен** пока существует сессия в Redis
5. **Swagger UI** автоматически добавляет токен после авторизации
6. **Postman** требует ручной настройки заголовков или использования переменных окружения

## 🔐 Авторизация/логаут с RSA

### Как это работает

#### 1. Генерация RSA ключей

- При первом запуске автоматически создаются пара ключей (приватный и публичный) в директории `keys/`
- Публичный ключ доступен через эндпоинт `GET /api/users/public-key/`
- Приватный ключ хранится на сервере и используется для расшифровки токенов
- Ключи генерируются с размером 2048 бит
- Используется алгоритм OAEP с SHA256 для шифрования

#### 2. Процесс логина (`POST /api/users/login/`)

1. Пользователь отправляет `username` и `password`
2. Сервер проверяет учетные данные через Django `authenticate()`
3. Создается уникальный `session_id` (UUID4)
4. `session_id` сохраняется в Redis с ключом `session_id` и значением `username`
5. Формируется токен в формате: `username:session_id`
6. Токен шифруется публичным RSA ключом (OAEP с SHA256)
7. Зашифрованный токен возвращается в заголовке `X-Auth-Token`
8. Также устанавливается cookie `session_id` для совместимости

**Пример запроса:**
```json
POST /api/users/login/
{
  "username": "testuser",
  "password": "password123"
}
```

**Пример ответа:**
- Заголовок: `X-Auth-Token: <зашифрованный_rsa_токен>`
- Cookie: `session_id=<uuid>`
- Body: `{"id": 1, "username": "testuser", "is_staff": false}`

#### 3. Использование токена

Токен можно передавать двумя способами:

1. **В заголовке X-Auth-Token:**
   ```
   X-Auth-Token: <зашифрованный_токен>
   ```

2. **В формате Bearer:**
   ```
   Authorization: Bearer <зашифрованный_токен>
   ```

**Как работает проверка токена (SessionMiddleware):**

1. Middleware проверяет наличие токена в заголовках `X-Auth-Token` или `Authorization`
2. Если токен найден, он расшифровывается приватным ключом
3. Из расшифрованного токена извлекаются `username` и `session_id`
4. Проверяется наличие сессии в Redis (ключ `session_id` должен существовать)
5. Сверяется, что значение сессии в Redis совпадает с `username` из токена
6. Если все проверки пройдены, устанавливается `request.user`
7. Если токен не найден или невалиден, проверяется cookie `session_id` как fallback

#### 4. Процесс логаута (`POST /api/users/logout/`)

1. Извлекается `session_id` из RSA токена (расшифровывается) или из cookie
2. Сессия удаляется из Redis (`session_storage.delete(session_id)`)
3. Cookie `session_id` очищается
4. После удаления сессии токен становится недействительным

**Пример запроса:**
```
POST /api/users/logout/
Headers: X-Auth-Token: <rsa_token>
```

**Важно:** После логаута токен перестает работать, так как сессия удаляется из Redis.

### Эндпоинты авторизации

- `POST /api/users/login/` - Вход в систему (получение RSA токена)
- `POST /api/users/logout/` - Выход из системы (удаление сессии)
- `GET /api/users/public-key/` - Получение публичного RSA ключа

## 📜 Lua скрипты

### Зачем используются

Lua скрипты выполняются непосредственно на стороне Redis, что позволяет:

- **Снизить сетевой трафик** - одна операция вместо множества запросов
- **Атомарность** - сложные операции выполняются атомарно
- **Производительность** - выполнение на стороне Redis быстрее множественных запросов
- **Безопасность** - минимизация рисков race conditions

### Текущий Lua скрипт

В проекте реализован Lua скрипт для получения активных пользователей с их сессиями.

#### Как работает скрипт

1. Использует `SCAN` для итерации по всем ключам в Redis (без блокировки Redis)
2. Для каждого ключа получает значение через `GET`
3. Фильтрует результаты:
   - Исключает пустые строки
   - Исключает значения с двоеточиями (Django кэш использует формат `key:value`)
4. Возвращает плоский массив: `[username1, session_id1, username2, session_id2, ...]`
5. Python код преобразует результат в словарь `{username: [session_ids]}`

#### Использование

**Функция:** `get_active_users_with_sessions_lua()` в `wells/redis_lua_utils.py`

**Эндпоинт API:** `GET /api/users/active-sessions/`

**Требования:**
- Пользователь должен быть аутентифицирован
- Пользователь должен иметь права модератора (`is_staff=True`)

**Пример запроса:**
```
GET /api/users/active-sessions/
Headers: X-Auth-Token: <rsa_token>
```

**Пример ответа:**
```json
{
  "active_sessions": {
    "user1": ["session-uuid-1", "session-uuid-2"],
    "user2": ["session-uuid-3"]
  },
  "total_users": 2,
  "method": "Lua script"
}
```


## 🔧 Технические детали

### RSA шифрование

- **Размер ключа:** 2048 бит
- **Алгоритм:** RSA-OAEP
- **Хеш-функция:** SHA256
- **Формат ключей:** PEM
- **Формат токена:** Base64-encoded зашифрованная строка `username:session_id`

### Middleware

- `SessionMiddleware` - проверяет RSA токены и устанавливает `request.user`
- Приоритет проверки: сначала RSA токен в заголовке, затем cookie `session_id`
